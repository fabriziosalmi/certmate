Certificate Management Settings

Automatically renew certificates when they approach expiration

Applies immediately, not with the Save button below. Off by default. When on, this instance contacts api.github.com once a day and the footer says when a newer release exists. A check that cannot reach GitHub reports unknown, never “up to date”.

Renew certificates when they have this many days left before expiration (default: 30 days), where that is at most half the certificate's lifetime. A shorter-lived certificate renews with a third of its lifetime left (half under 10 days), and a window its CA publishes (ARI) can move the date. The API reports the instant for each certificate (renews_at). Renewals this setting brings ahead of that are capped at 10 per nightly run by default.

How long the dashboard's deployment status of a certificate is kept before it is checked again (default: 300 seconds)

 

When set, each certificate is also written as an encrypted cert.pfx (PKCS#12) using this password, downloadable for Windows hosts. A blank field keeps the current password; to turn the export off, tick the box above and save. Stored like other secrets and never shown again after saving.

Applied to any new certificate that does not pick a per-cert override. Renewals always keep the shape of the cert at creation time.

The key CertMate generates for a new client certificate that does not pick one. A renewal keeps the kind of key of the certificate it replaces.

API Security Settings

This token has full admin access. It cannot be changed here. To rotate it, set API_BEARER_TOKEN (or API_BEARER_TOKEN_FILE, the path of a file that holds it, which wins when both are set) to a new random token of at least 32 characters, for example from openssl rand -hex 32, and restart CertMate: the old token then stops working. For scripts and agents, create a scoped key in Settings → API Keys instead.
