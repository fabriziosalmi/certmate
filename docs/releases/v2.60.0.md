## v2.60.0 (overlapping listings no longer take the server down, and /health answers on a port no request can take)

A minor release. The API contract moves from 2.75 to **2.79** (#1551, #1552, #1553, #1558). Every fix in it comes with a test that was run against the code before the fix and failed.

- **Overlapping certificate listings share one read** (#1557, part of #1463). Each `GET /api/certificates` read every certificate itself on a pool of threads of its own, so listings that overlapped multiplied the work. Measured with 2,000 certificates on the image: four cold listings at once took 181 s each, and now take 45 s each, as long as one. A listing never receives what a write it began before has changed.
- **/health answers on a port of its own** (#1558, part of #1463, contract 2.79). The image serves `/health` on `HEALTH_PORT` (8001) as well, from a thread no request can take, and its `HEALTHCHECK`, both compose files and the Helm chart's probes ask that port. Measured: with 8 slow listings holding every request thread, `/health` on 8001 answered in 2 ms while 8000 did not answer in 10 s. `/health` now also says whether requests still finish, and answers `503` with status `unhealthy` when every request thread has been busy with nothing finishing for `CERTMATE_HEALTH_STALL_SECONDS` (by default a minute past `GUNICORN_TIMEOUT`, 360 s in the image). `GUNICORN_THREADS` sets the request threads. See [Monitoring](../monitoring.md#the-health-port).
- **An external import keeps single-label and IP names** (#1553, #1549, part of #1538, contract 2.78). A certificate migrated from a private CA may carry `my-host-name` or an IPv4 or IPv6 address beside its domain; it is filed under its first DNS name with a domain, or its IPv4 address when it has none. The import preview now runs the same check as the import.
- **A reissue takes the CA account it is given** (#1551, closes #1465, contract 2.76), from the API, and from the CLI (`certmate cert reissue --ca-account`) and the MCP tool in their next releases (#1555, closes #1546). "Global default" and "Default for" in the picker mean the defaults.
- **One email address belongs to one user** (#1552, closes #1466, contract 2.77), and SSO neither links nor creates a user for an address another user holds.
- **Two user writes at the same time both land, or one is refused** (#1559, closes #1544). Two creates at once could both answer success and lose one user, and two demotions at once could leave no admin.
- **CRLs name their CA correctly** (#1550, part of #1537; #1554, closes #1545): the issuer is the signing CA's subject, also for an intermediate, and every CRL carries the CA's Authority Key Identifier and a CRL Number that only grows.
- **PowerDNS is answered by CertMate's own hook** (#1462, closes #1432, contributed by manss-rf), so it works in the default image, finds the zone of a sub-domain, and never follows a redirect with its API key.

Upgrading: the container now listens on 8001 for `/health` as well, inside the container only; nothing is published. A healthcheck of your own that asks `:8000/health` keeps working.
