## v2.59.0 (acme-dns issues and renews again, and the interface says what each control does and what it found)

A minor release. The API contract moves from 2.68 to **2.75** (#1515, #1526, #1527, #1528, #1529). It fixes one issuance bug that affected every release since v2.51.1, and it carries the fixes of the UX perception audit (#1511), each with a test that was run before it and failed.

- **acme-dns issues and renews again** (#1542, closes #1534). From v2.51.1 to v2.58.0 the DNS alias hook failed before sending any request when certbot started it, with "attempted relative import with no known parent package", so no acme-dns certificate could be issued or renewed. Other providers were not affected. The hook now runs as a script, and it refuses HTTP redirects, so the acme-dns credentials are never sent to a host other than the configured `api_url`. A test runs the hook the way certbot does, and a check keeps the same import bug out of every hook.
- **CA and DNS accounts carry their last credential check** (#1529, contract 2.75). A check result says only what that check proved.
- **First run says what it did** (#1528, contract 2.74): the wizard lists what it saved and what does not take effect, the login names the admin just created, and a failed validation or rate limit at production Let's Encrypt suggests staging.
- **Settings show their real state** (#1527, contract 2.73): event chips, ACME status, the field a refused save names, and whether a section waits for Save.
- **Activity records client certificates and every download** (#1526, contract 2.72), and a hook test reads as a test.
- **A CA account that cannot issue says what it lacks** (#1515), and the account picker names accounts by their name.
- **The DNS token saved in Settings is the one issuance uses** (#1516), no provider has an empty placeholder account, and the providers stay in reach under HTTP-01.
- **A failed renewal stays one certificate** (#1519), with its last attempt on the row and in the detail panel; a failed renewal says what to check and that the previous certificate is still in place (#1510).
- **The API Bearer Token field is read-only and never sent** (#1522), so a value in it can no longer make every Settings save fail.
- **A renewal is Overdue in red or Due in amber on every page** (#1523), and each counter shows the rows it counts.
- **Interface consistency and accessibility** (#1508, #1509, #1513, #1517, #1518, #1520, #1524, #1525, #1530, #1531, #1532): certificate lists are tables that work on a phone; dialogs keep and return focus; toasts can be read and reached; one button size, one status pill and one page frame; every text field shows a 2 px focus ring; headings never skip a level and icons are hidden from screen readers.
- **Documentation** (#1512, #1514): Help gives one place for API tokens and covers client certificates, the ACME server, Inventory and crypto readiness; four pages now say what the code does about backup order, restore in setup mode, held certificates and the CA keys.
- **The image is built on the current `python:3.12-slim-trixie`** (#1547): Python 3.12.16 on Debian 13.8.

Open follow-ups from the audit are listed in #1533.
