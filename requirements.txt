# Certificate management
#
# certbot, acme, josepy and the official certbot-dns-* plugins move TOGETHER.
# Each plugin from certbot's own release train declares `certbot>=` and `acme>=`
# its own version, so one of them moving alone either refuses to install or drags
# the others off the pin; Dependabot is told to leave the family alone and the
# set is moved by hand, with the lock regenerated (#103). 5.8.0 is the first line
# since 2.10.0 that CertMate runs: measured against it, the real-certificate
# end-to-end suite passes 24 of 24 on Let's Encrypt staging, a certificate issued
# by 2.10.0 renews under 5.8.0 and the reverse, and CertMate's own strategy for
# each of 23 providers behaves as it does on 2.10.0.
certbot==5.8.0
# acme is the ACME protocol client itself, the most protocol- and security-
# sensitive package in the tree. certbot declares a bare `acme>=` its own
# version, so without this line the version would be whatever PyPI served and a
# clean install would not reproduce the one that was tested.
acme==5.8.0
josepy==2.2.0

# Held at 2.0.1 DELIBERATELY — do not "upgrade" this to 3.0.0.
#
# 3.0.0 swapped its dependency from upstream `dns-lexicon` to the third-party
# fork `dns-lexicon-coop`. Both distributions ship the SAME top-level
# `lexicon/` package, so pip installs one over the other with no warning and
# no conflict: whichever lands last wins, which made the `dns-lexicon==3.25.1`
# pin below unenforceable and put an unvetted fork into the default image.
# `modules/core/dns_alias_hook.py` imports `lexicon.client`, so alias mode was
# the thing running whichever copy won the coin toss.
#
# The downgrade costs nothing: every .py file in the plugin is byte-identical
# between 2.0.1 and 3.0.0 (verified by sha256 against both wheels on PyPI).
# The two releases differ ONLY in that dependency declaration.
# tests/test_dependency_collisions.py fails if the fork comes back.
